# Требования к внешней интеграции с платформой «Умный дом»

**Новые услуги:** интеллектуальный домофон (видеовызов, открытие по звонку, открытие по лицу) и интеллектуальный шлагбаум (открытие из приложения и по номеру автомобиля). Услуги предоставляет партнёр, жильцы пользуются ими через мобильное приложение

**Главный принцип:** PropDevelopment решает, у кого есть доступ, а платформа партнёра только выполняет переданные права. Партнёр работает только со шлюзом внешних интеграций и не имеет доступа к CRM, tenant-core-app и хранилищу данных

---

## 1. Требования к безопасности

1. **Договор поручения обработки ПДн.**
2. Партнёр получает только обезличенный ID жильца, адрес доступа (ЖК, подъезд, квартира, парковка), срок действия прав и номера автомобилей. ФИО, телефон и паспортные данные не передаются.
3. Фото лица и шаблоны остаются у партнёра или в ЕБС, у нас — только отметка о согласии.
4. **Шифрование:**
   - при передаче — TLS 1.2 и выше;
   - при хранении — у обеих сторон.
5. Партнёр видит данные только тех ЖК, которые к нему подключены. Жилец видит видео и журнал только своего подъезда.
6. При удалении члена семьи права, номера автомобилей и биометрия удаляются у партнёра автоматически.
7. Устройства подключены к отдельной сети и общаются только с платформой партнёра
8. Если наши системы или платформа недоступны, работают ключ, код и вызов квартиры
9. Все команды и события записываются у обеих сторон и передаются в систему мониторинга ИБ (SIEM).

---

## 2. Протоколы аутентификации и авторизации

| Кто с кем | Аутентификация | Авторизация |
| --- | --- | --- |
| Жилец - мобильное приложение - наши системы | OpenID Connect / OAuth 2.0 (Authorization Code + PKCE) через auth-service-1 (Keycloak). Короткоживущий JWT-токен | Роли и атрибуты в токене |
| API Gateway - внутренние сервисы | Проверка JWT по ключам Keycloak | Сервис проверяет, что пользователь имеет право на конкретную квартиру и устройство |
| Наши системы - платформа партнёра | mTLS + OAuth 2.0 Client Credentials | Права (scope) ограничены функциями интеграции и списком наших ЖК |
| Платформа партнёра - наши системы (события) | mTLS | Принимаем только события по нашим устройствам |
| Платформа партнёра - устройства | mTLS с отдельным сертификатом для каждого устройства | Зона ответственности партнёра |

## 3. Взаимодействие систем

**Основные сценарии:**

1. **Выдача доступа.** Собственник добавляет члена семьи, гостя или номер автомобиля. Приложение отправляет запрос через API Gateway в smarthome-access-service. Сервис проверяет права, сохраняет изменение у себя и передаёт его партнёру через шлюз. Каждую ночь списки прав сверяются.

2. **Звонок в домофон:**
   1. Гость звонит, и партнёр присылает событие «входящий вызов».
   2. smarthome-access-service находит жильцов квартиры и отправляет им push-уведомление.
   3. Приложение получает у нас разовый токен и подключается к видео партнёра.
   4. Жилец нажимает «Открыть»: команда проходит через наши системы с повторной проверкой прав и уходит к партнёру.

3. **Въезд по номеру автомобиля.** Номер регистрируется в приложении и передаётся партнёру. Шлагбаум открывается при распознавании номера, а событие въезда приходит к нам.

4. **Отзыв доступа.** CRM собственников публикует в Kafka событие о смене собственника. smarthome-access-service удаляет у партнёра права, номера автомобилей и биометрию и ждёт подтверждения.
